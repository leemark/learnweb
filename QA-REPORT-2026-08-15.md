# learn.web — full-site QA report

Audit date: 2026-08-15
Production reviewed: <https://learnweb.cc/>
Repository baseline: `main` at `ae2bbac`

## Executive assessment

learn.web already has an unusually strong foundation: a distinctive visual identity,
36 useful project-based lessons, progressive enhancement, real in-browser workspaces,
local-first persistence, static indexable lesson URLs, robust Back/Forward behavior,
offline support, and a clear privacy/trust layer. The normal product flows are stable
across Chromium, Firefox, and WebKit. There are no ordinary-use P0 release blockers.

The site is not yet at its ceiling. The largest quality gap is that the scroll-reveal
system works against both accessibility and mobile performance. The largest product
gaps are search that contradicts its own examples, duplicate search results, no clear
way to resume an unfinished draft, and a production code runner that can fail silently
when its third-party CDN is unavailable. Discovery foundations are good, but the
course schema is not yet eligible for Google's course-list treatment and search has
not yet caught up with the newly published lesson URLs.

## Remediation completed in this worktree

These changes are implemented and verified locally but are **not deployed to
`learnweb.cc` yet**:

- Replaced low-opacity/blur reveals with transform-only motion, exempted the hero from
  reveal animation, enlarged footer targets, corrected group semantics and progress
  names, changed the modal lesson title to `h2`, and made path/placement focus placement
  and restoration reliable across Chromium, Firefox, and WebKit.
- Made the homepage preview genuinely lazy. The UI now waits for a sandbox heartbeat,
  times out visibly, offers Retry, and never claims `Ready` before the isolated runner
  is ready. The third-party runner URL remains an operational dependency to replace.
- Expanded search with path labels, objectives, guide content, missions, and synonyms;
  `WCAG` now works and lessons no longer appear twice. A separate static-page action on
  the same result remains a useful polish item.
- Persisted the last-opened lesson and backup state; My Studio now shows Resume, draft
  count, and draft rows without requiring accounts.
- Added Google-eligible six-course `ItemList`/`ListItem` structure to `/learn/`, explicit
  Twitter/X metadata to generated pages, and an early interactive-studio CTA on every
  static lesson. Generator checks enforce the structure.
- Corrected path time estimates, onboarding/shortcut/final-CTA copy, certificate trust
  language, analytics/privacy wording, and delayed GA4 until first interaction/idle.
- Added deterministic browser coverage for runner outages, focus, search, and draft
  round-trips, plus an explicit `--skip-isolation` mode so the known headless process
  limitation cannot hang the rest of the regression suite.

## Priority findings

### P1-01 — Scroll reveals harm contrast, LCP, and main-thread work — fixed locally

**Evidence**

- `styles.css` animates `.reveal` from opacity `.15` plus blur and `.feature-row`
  from opacity `.25`.
- Normal-motion accessibility checks found contrast as low as 2.11:1 in dark mode
  and 1.75:1 in light mode while the animation was in progress.
- Lighthouse identified `YOUR MATERIAL.` as the LCP element with about 2.1 seconds of
  element-render delay and reported 5.3 seconds of main-thread work, dominated by
  style/layout.

**Required improvement**

Use transform-only reveals for below-fold content, never animate readable text through
low opacity or blur, and exempt the first viewport from view-timeline animation. Keep
reduced-motion behavior. Re-run axe during scroll and mobile Lighthouse.

### P1-02 — The production code runner can fail silently — resilience fixed locally; hosting open

**Evidence**

- Production loads `lab-runner.htm` from
  `raw.githack.com/leemark/learnweb/main`, a third-party CDN and mutable branch.
- When that request was blocked, the frame showed a browser error but the homepage lab
  still said `Ready`; the lesson workspace showed no timeout, retry, or fallback.
- The runner is eagerly requested before a learner uses the lab.

**Required improvement**

Lazy-load the runner on first use, add a ready timeout and visible retry/error state,
and stop calling the lab ready before the handshake succeeds. Move the runner to a
stable first-party isolated origin or immutable versioned URL and monitor availability.
The first-party origin/hosting change is operational work beyond a static code patch.

### P1-03 — Site search is internally inconsistent and duplicates lessons — core fixed locally

**Evidence**

- The placeholder suggests `WCAG`, but `WCAG` returns no results.
- Search indexes title/type/description but not path label, topic tags, objectives,
  guide copy, or synonyms.
- Every lesson is indexed twice—interactive and static—and results are truncated at 12,
  so duplicates can hide useful matches.

**Required improvement**

Build one richer record per lesson, include labels/topics/objectives and intentional
synonyms, and present `Open studio` and `Read page` as actions on one result. Add tests
for every example shown in the search UI, including WCAG, CSS, performance, and agents.

### P1-04 — Unfinished work is saved but effectively invisible — fixed locally

**Evidence**

- Workspaces and notes persist locally, but My Studio renders only submitted artifacts.
- There is no Resume last lesson action, draft count, or in-progress list.

**Required improvement**

Persist last-opened lesson, expose one prominent Resume action, show drafts/in-progress
items in My Studio, and distinguish `draft`, `submitted`, and `complete`. This is the
highest-value retention improvement because it makes the existing local-first work
discoverable without introducing accounts or notifications.

### P1-05 — Course markup is valid Schema.org but not Google course-list eligible — fixed locally

**Evidence**

- Path pages emit `Course` and lesson pages emit `LearningResource`.
- `/learn/` emits a generic `LearningResource` with `hasPart`, not the required
  `ItemList`/`ListItem` course carousel structure.
- Google currently requires at least three courses, an ItemList summary, unique URLs,
  and valid course/provider data for course-list eligibility.

**Required improvement**

Emit a six-item `ItemList` on `/learn/`, pair it with the path Course records, use one
truthful provider identity consistently, and validate the generated output. Add explicit
Twitter/X title, description, and image metadata on shareable lesson/path pages instead
of relying only on Open Graph fallback.

Reference: <https://developers.google.com/search/docs/appearance/structured-data/course>

### P1-06 — Important claims need nearby primary sources — open editorial/data-model work

**Evidence**

- Lessons show author and last-verified date but do not expose a references section.
- Standards and current-platform claims are often correct, but readers cannot verify
  them without leaving the lesson and searching independently.

**Required improvement**

Add a compact Sources / Verify this section to lessons that make standards, browser,
search, privacy, or AI-safety claims. Store sources in curriculum data, render them in
interactive and static lessons, and emit `citation` or `isBasedOn` where appropriate.
Prioritize official W3C, web.dev/MDN/specification, Google Search Central, and primary
research sources. Do not add `llms.txt` or generic FAQ markup as an AEO shortcut.

Google's current guidance explicitly prioritizes crawlability, unique non-commodity
content, clear structure, and established SEO over AEO/GEO hacks:
<https://developers.google.com/search/docs/fundamentals/ai-optimization-guide>

## P2 findings

### Accessibility and interaction polish

- Remove `aria-label` from unlabeled generic containers or add an appropriate role:
  `.hero-specimen` and `.preview-sizes` should be real named groups if the label matters.
- Focus the first useful control or heading when path/placement dialogs open; do not
  land on a generic shell solely because it has `tabindex=-1`.
- Include visible `0/36` text in the compact progress control's accessible name.
- Increase footer link/button target height/spacing to at least the WCAG 2.2 minimum.
- Change the dynamic lesson dialog title from a second document `<h1>` to a heading
  level that reflects its modal placement.

WCAG 2.2 remains the recommended target and includes Focus Not Obscured and Target Size:
<https://www.w3.org/TR/WCAG22/>

### Performance and privacy

- GA4 accounted for about 0.57 s of scripting and roughly 68 KiB of unused JavaScript
  in the conservative Lighthouse run. Load analytics after the first useful render/idle
  period and keep the no-learner-content regression test.
- Replace `anonymous page-view statistics` with precise language such as `aggregate
  page-view measurement`; do not imply that a third-party analytics request is identity-
  free without a documented configuration and policy basis.
- Google Fonts add third-party connections and several WOFF2 requests. Self-hosting the
  selected subsets would improve privacy, repeatability, and cache control, but is less
  important than fixing reveal motion and analytics startup.
- Static assets use `max-age=600`. A later hosting/build pass should add content hashes
  and immutable caching before pursuing larger code splitting; current first-load weight
  is modest.

Core Web Vitals targets should be evaluated at the 75th percentile: LCP <= 2.5 s,
INP <= 200 ms, and CLS <= 0.1:
<https://web.dev/articles/defining-core-web-vitals-thresholds>

### Content, onboarding, and trust

- Correct path estimates using one transparent rounding rule. Current module totals are:
  Foundations 7h, Platform 8h55m, UX 7h25m, Accessibility 7h30m, Search 7h10m,
  AI 8h20m; several homepage cards materially understate them.
- Change the closing CTA from `Start with the platform` to Foundations or placement;
  the current CTA contradicts the product's own On-ramp designation.
- Explain whether paths are independent and give a recommended sequence.
- Show `Ctrl/Command + K` or a platform-aware shortcut, not Command-only copy.
- Add official support/source links to the six current-platform feature cards.
- Move or repeat the static page's `Open the interactive lesson` CTA near the top so
  search visitors understand the read-only page versus studio experience immediately.
- Strengthen non-code quality checks beyond 30 characters. Require concrete evidence,
  a decision, and self-review signals; label the certificate and share copy as locally
  completed/self-attested rather than independently accredited.
- Search/share text should link to or export the artifact itself when possible, not only
  make a completion claim.

Baseline 2026 is the appropriate source for current platform status:
<https://web.dev/baseline/2026>

### Hosting and security hardening

The GitHub Pages responses did not expose CSP, HSTS, `X-Content-Type-Options`,
`Referrer-Policy`, `Permissions-Policy`, or cross-origin isolation headers. Some of these
are hosting-level controls and cannot be solved reliably with static HTML alone.

Required hosting follow-up: choose a front door that can set headers, define a CSP that
permits only the app's known analytics/font/runner dependencies, add Referrer and
Permissions policies, and evaluate COOP/COEP only after confirming the cross-origin
preview and fonts continue to work. Do not ship an untested CSP that breaks the lab.

### Indexing and measurement

- Submit the current sitemap in Google Search Console and inspect representative hub,
  path, and lesson URLs. Request indexing only for representative/high-priority pages;
  crawling is not guaranteed.
- Establish Search Console and GA4 baselines for impressions, clicks, landing pages,
  placement starts/completions, lesson starts, artifact submissions, return visits, and
  completion. Keep analytics free of learner-authored content.
- Use Search Console's generative-AI reporting if it is available for this property;
  rollout is not guaranteed for every site.
- Add real-user Core Web Vitals collection or use Search Console/CrUX before claiming
  production LCP/INP/CLS quality. Build success and one Lighthouse run are not field proof.

## P3 / later opportunities

- Self-host fonts and use versioned/immutable assets.
- Split the interactive curriculum payload so first-time homepage visitors do not need
  all 36 lesson guides before opening a lesson.
- Add a genuinely safe maskable app icon rather than declaring the same SVG as both
  `any` and `maskable` without a verified safe zone.
- Expand the highest-opportunity static lessons with additional worked examples,
  failure modes, rubrics, source-backed comparisons, and original evidence. Current
  generated pages are concise (roughly 398–534 words including page chrome); depth
  should follow demonstrated search/learner demand, not a generic word-count target.
- Consider learner-hosted artifact links or an explicit publish workflow while preserving
  the current no-account/local-first position.

## Recommended execution order

1. Motion/contrast/LCP correction and accessibility target/name/focus fixes.
2. Runner readiness/error/lazy-load resilience.
3. Search consolidation and WCAG/synonym coverage.
4. Resume/draft surfacing.
5. Course-list JSON-LD, explicit social metadata, and early studio CTA.
6. Truthful time estimates, onboarding copy, certificate/share language, and analytics
   deferral/privacy wording.
7. Source-data model and editorial citations, then Search Console/indexing follow-up.
8. Hosting headers, stable runner origin, immutable assets, field measurement, and
   deeper content based on evidence.
