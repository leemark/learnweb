WCAG 2.2 / Inclusive Design

Accessibility

Accessibility as a design and engineering practice—not a checklist added after launch.

By the end of this path

Audit and repair a real interface through automated checks, keyboard use, screen-reader testing, zoom, and human evaluation.

Lessons

Six studio lessons

  • 01 People before criteria
    Understand disability, assistive technology, situational constraints, and the limits of conformance.     55 min
  • 02 Semantic structure and names
    Create a reliable accessibility tree with native HTML, useful labels, and disciplined ARIA.     75 min
  • 03 Keyboard and focus systems
    Design logical order, visible focus, unobscured targets, skip paths, and robust modal behavior.     80 min
  • 04 Visual access and reflow
    Test contrast, text spacing, zoom, motion, color independence, forced colors, and responsive reflow.     70 min
  • 05 Forms, errors, and authentication
    Make instructions, validation, recovery, target sizes, and sign-in flows understandable.     75 min
  • 06 Test beyond the scanner
    Combine axe-style automation, keyboard checks, screen readers, browser zoom, and user testing.     95 min
